Chapter 1

Why it matters

Part 1 · Two worlds
SamThe README says source .venv/bin/activate. My laptop says “not recognized”. Is my laptop broken?
SnapNot broken, just bilingual! Linux and macOS are both Unix-style systems and share one language. Windows has its own. Research code, servers and clusters almost always speak Unix.

So the README is fine and your laptop is fine. They just use different dialects. This appendix is the phrasebook.

Chapter 2

Paths: two ways to say “here”

Part 1 · Two worlds

Windows

C:\Users\sam\thesis\data.csv

  • Starts with a drive letter (C:, D:…): one tree per drive
  • Separator: backslash \
  • Home folder: C:\Users\sam, also %USERPROFILE% or $env:USERPROFILE
  • Data.csv and data.csv are the same file

Linux / macOS

/home/sam/thesis/data.csv

  • One single tree that starts at / (root); no drive letters
  • Separator: forward slash /
  • Home folder: /home/sam (macOS: /Users/sam), also ~ or $HOME
  • Data.csv and data.csv are different files

Folder trees, . and .., absolute vs relative paths: Issue #0 · Ch. 4

Write paths that work on both 
Python
# breaks on Linux, the cluster, your teammate's Mac
df = pd.read_csv("C:\\Users\\sam\\thesis\\data\\raw.csv")

# works everywhere
from pathlib import Path
DATA = Path("data")                 # relative to the project folder
df = pd.read_csv(DATA / "raw.csv")  # pathlib picks the right separator

Rule of thumb: no drive letters and no backslashes in code you share. Use pathlib (or forward slashes, which Python on Windows also accepts) and relative paths.

The case trap
SnapOn Windows, open("Data/Raw.CSV") finds data/raw.csv. On the cluster it doesn't. Match the capitals exactly, and you'll never meet this bug.

Chapter 4

Invisible differences

Part 1 · Two worlds
Line endings: the ghost character
SnapEvery line of text ends with an invisible marker. Windows uses two characters (\r\n, “CRLF”), Linux uses one (\n, “LF”). Usually nobody notices… until a script written on Windows runs on Linux.
gpu4edu:~$ bash train.sh
train.sh: line 2: $'\r': command not found
gpu4edu:~$ ./train.sh
/bin/bash^M: bad interpreter: No such file or directory

That \r and that ^M are the ghost: a Windows line ending inside a Linux script.

Bust the ghost 
# one file, on Linux / WSL
$ sudo apt install dos2unix
$ dos2unix train.sh
# .gitattributes (in the repo)
* text=auto
*.sh text eol=lf

Also set your editor to save with LF line endings. The .gitattributes file makes Git store and check out text files consistently for everyone.

Chapter 5

What is WSL?

Part 2 · WSL
SnapThe Windows Subsystem for Linux runs a real Linux, usually Ubuntu, right next to Windows. It isn't a translator or an imitation: it's actual Linux with its own files, its own users and its own software.

From Linux, your C: drive is at /mnt/c. From Windows Explorer, type \\wsl$ in the address bar to see your Linux files. New installs use WSL 2, which runs Linux in a lightweight virtual machine.

Why it's the best option
  1. Commands from READMEs, tutorials and these issues work as written.
  2. It behaves like the server you'll run on, so fewer surprises later.
  3. Linux package managers: sudo apt install almost anything.
  4. With an NVIDIA GPU, even CUDA works inside WSL 2.
Chapter 6

Can my laptop run it?

Part 2 · WSL
Three checks before you install
1

Windows version

Windows 11, or Windows 10 version 2004 or newer (build 19041+).

Check: press Win+R, type winver, Enter.

2

Virtualization on

Your processor's virtualization feature must be enabled.

Check: Task Manager (Ctrl+Shift+Esc) → Performance → CPU → “Virtualization: Enabled”. If it says Disabled, it's switched on in the BIOS/UEFI settings; how depends on your laptop brand.

3

Allowed to install

You need administrator rights on the laptop.

University or company-managed laptops may block this, or block WSL networking. Ask your IT service desk first.

Very old processors (around the Intel Core 2 Duo era) can't run WSL 2 at all. Older Windows 10 versions need the manual install steps in Microsoft's documentation (Chapter 11).

Chapter 7

Install WSL

Part 2 · WSL
Step 1 · One command

Right-click PowerShell in the Start menu, choose Run as administrator, then:

PS C:\WINDOWS\system32> wsl --install

This switches on the Windows features WSL needs and installs Ubuntu. When it's done, restart your computer.

Step 2 · Create your Linux user

After the restart, Ubuntu opens (or start it from the Start menu). The first launch unpacks files, then asks for:

Enter new UNIX username: sam
New password: (nothing appears while typing: normal!)
Retype new password:
sam@laptop:~$

This Linux username and password are separate from your Windows login. You'll need the password for sudo.

Step 3 · Update and check 
sam@laptop:~$ sudo apt update && sudo apt upgrade

Windows doesn't update your Linux for you: run this now and then.

PS> wsl -l -v
  NAME      STATE      VERSION
* Ubuntu    Running    2

VERSION 2 is what you want.

If step 1 doesn't go as planned
You see
Try
The WSL help text instead of an install
WSL is already partly installed. List the distributions with wsl --list --online, then wsl --install -d Ubuntu.
Install stuck at 0.0%
wsl --install --web-download -d Ubuntu downloads it another way.
Error 0x80370102
Virtualization is off: see Chapter 6, check 2. Also switch on the Windows feature “Virtual Machine Platform”, then restart.

Tip: install Windows Terminal from the Microsoft Store (already included in Windows 11). It holds PowerShell and Ubuntu in tabs side by side.

Chapter 8

Living in WSL

Part 2 · WSL
Rule #1: keep projects on the Linux side
Fast/home/sam/thesis(~/thesis in Ubuntu)
Slow/mnt/c/Users/sam/thesisWindows files, reached from Linux

Working across the two file systems is much slower: pip install, git status and training data loaders all crawl. Clone your repos inside your Linux home folder.

sam@laptop:~$ mkdir -p ~/projects && cd ~/projects
sam@laptop:~/projects$ git clone git@github.com:sam/thesis.git
sam@laptop:~/projects$ explorer.exe .     # open this folder in Windows Explorer
Install your tools inside Ubuntu 
$ sudo apt install git python3 \
    python3-venv python3-pip

Linux has its own copies of everything. Git, Python and conda installed on Windows don't count inside WSL.

Two of everything
SnapWindows and WSL are two separate homes. Each has its own Git settings (git config --global …) and its own SSH keys (C:\Users\sam\.ssh vs ~/.ssh). Set them up once inside WSL.

SSH keys: Issue #3 · Ch. 2 · Git setup: Issue #1 · Ch. 2

Handy from PowerShell 
PS> wsl              # open Linux here
PS> wsl --shutdown   # stop it (frees memory)
PS> wsl --update     # update WSL itself
Got an NVIDIA GPU?

CUDA works inside WSL 2. Install the normal NVIDIA driver on Windows only. Don't install a Linux display driver inside WSL: NVIDIA's guide explains why.

Your editor

Many editors on Windows can open a folder that lives inside WSL directly; look for “WSL” in your editor's documentation. Terminal editors such as nano and vim run inside Ubuntu as usual.

Chapter 9

No WSL? Plan B

Part 2 · WSL
Git Bash

Comes with Git for Windows: a bash terminal with git, ssh, ls, cat and friends. Enough for Issue #0, Issue #1 and connecting to a server.

It isn't a full Linux: no apt, and some tools are missing. Paths look like /c/Users/sam.

PowerShell + ssh

Windows 10 (1809+) and 11 include an OpenSSH client. If ssh isn't recognized, add “OpenSSH Client” under Settings → Optional features.

PS C:\Users\sam> ssh u123456@server.example.org

Then do the Linux part on the server itself.

Mix and match
SnapPlenty of people write code in Windows apps, keep it in Git, and run it on a Linux server. Just remember Chapters 2–4: forward slashes, matching capitals, LF line endings.
