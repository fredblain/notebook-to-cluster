Chapter 1

Found a paper with code!

Part 1 · Find your way
Literature review, week 3
SamThis paper is perfect for my thesis, and it has code! …But there's no notebook. Where do I even start?
Notebook vs repo
SnapSame ideas, different packaging! A notebook is cells you run in the browser. A repo splits the code over .py files, and you run them from the terminal.
Before you clone
SnapIs this repo worth an afternoon? You can tell a lot from its GitHub page in five minutes, without installing anything.
Triage checklist: is this repo worth your time?
CheckGreen lightRed flag
READMEExplains how to install and run, with an example commandEmpty, a title only, or “code coming soon”
ActivityCommits after the paper came out; questions in Issues get answersLast commit years ago; Issues full of unanswered “doesn't run” reports
Dependenciesrequirements.txt, pyproject.toml or environment.yml, with versionsNo dependency file at all: you'll have to guess every package
DataDownload script or link, or a public benchmark dataset“Available on request”, or human-subject data that needs ethics approval or a data use agreement
Trained modelsPretrained weights or checkpoints provided (e.g. on Hugging Face)You'd have to train everything from scratch
HardwareRuns on a single GPU, or even a laptop CPU for a small demoThe paper used 8 GPUs for 3 days
LicenseMIT, Apache, BSD, GPL… (a LICENSE file)No license: legally, you may read the code but not reuse it
Matches the paperREADME links the paper; a release or tag marks the paper's versionThe code clearly does something different from what the paper describes
Mostly greenClone it and try to run it (this issue).
Some redStill worth reading to understand the method. Plan extra time before you rely on it.
Mostly redNote it in your literature review (“code released but not runnable”) and move on. That's a finding too.

Tip: the Issues tab is also a preview of the errors you're about to hit, and often of their fixes.

Worth it? Get a copy
SnapMostly green lights? Clone it. Your mission: can I run it, and do I get roughly the numbers in the paper?
$ git clone https://github.com/some-lab/fancy-model.git
$ cd fancy-model
$ git log --oneline | head -5   # is anyone still working on it?

The green Code ▸ Download ZIP button works too, but you get no history and can't pull updates. Git Good · Ch. 8: clone ↗

Two habits from minute one 
# 1. note exactly which version you started from
$ git rev-parse --short HEAD
3f2a9c1
# 2. keep your own changes on a branch
$ git switch -c my-experiments

Put the paper, the repo link and the commit ID in your literature-review notes. If you end up using the code in your thesis, that ID goes in your methods section. The branch keeps the authors' original code one git switch main away. Git Good · Ch. 6: branches ↗

Jupyter → repo dictionary
In a notebook you…In a repo you…
download one .ipynb fileclone the whole folder with git clone (Chapter 1)
write code in cellsfind it in functions and classes spread over .py files (Chapters 2–3)

see a red error box under a cellsee the same traceback in the terminal (Chapter 9)
Chapter 2

The map of a research repo

Part 1 · Find your way
Every repo is different, but most look a lot like this 
fancy-model/
├── README.md            ← START HERE: what it does, how to install, how to run
├── requirements.txt     ← the packages it needs (or pyproject.toml / environment.yml)
├── configs/
│   └── base.yaml        ← hyperparameters, file paths, random seed
├── data/                ← often EMPTY in the repo: the README says how to download
├── scripts/
│   ├── download_data.sh
│   └── train.sh         ← the exact commands the authors ran (gold!)
├── src/fancy_model/     ← the actual code, as a Python package
│   ├── data.py          ← loading & preprocessing
│   ├── model.py         ← the architecture
│   ├── train.py         ← training loop
│   └── evaluate.py      ← computes the numbers in the paper
├── notebooks/           ← demos & exploration: tempting, but often out of date
├── tests/               ← small checks that the code works
└── LICENSE              ← what you are allowed to do with it
SnapBefore reading any code, walk around the outside. Ten minutes here saves you a day later.
Look around from the terminal 
$ ls -a                  # incl. hidden files
$ tree -L 2              # folder overview
$ find . -name "*.py" | wc -l
$ less README.md         # q to quit

No tree? brew install tree on macOS, sudo apt install tree on Ubuntu.

Chapter 3

Reading order: follow one thread

Part 1 · Find your way
SnapDon't read every file top to bottom. Follow the path one experiment takes: from the command you run, to the number in the paper.
Find the front door

The script you run usually has an if __name__ == "__main__": block and parses command-line arguments.

$ grep -rn "__main__" --include="*.py" .
$ grep -rln "argparse\|hydra\|click" --include="*.py" .
Jump to a definition 
$ grep -rn "def compute_loss" src/
src/fancy_model/train.py:52:def compute_loss(...)
$ grep -rn "class FancyModel" .
$ grep -rn "batch_size" configs/ src/

Faster alternative: rg (ripgrep). In Vim, :vimgrep or ctags lets you jump straight to the definition under the cursor.

Keep a case file 
# notes.md — fancy-model
- entry: scripts/train.sh → src/fancy_model/train.py
- config: configs/base.yaml (lr, batch_size, seed)
- data: expects data/raw/*.jsonl (download_data.sh)
- Table 2 = evaluate.py --split test
- ??? what is `alpha` in compute_loss

Writing down the path, and your open questions, is the most useful thing to bring to a supervisor meeting.

Chapter 4

Why environments?

Part 2 · Environment
Without environments
SamIn Jupyter I just type !pip install in a cell when something's missing. Easy.
With environments
SnapThat installs into whatever Python your kernel uses, often one shared by all your projects. An environment is a separate box of packages per project: box A has numpy 1.23, box B numpy 2.0. No fights.
House rules
  1. One project, one environment. Not one giant env for your whole degree.
  2. Never sudo pip install. That changes the Python your operating system relies on.
  3. Environments are disposable. Broken? Delete the folder and rebuild it from the requirements file.
  4. Don't commit the env folder. Add .venv/ to .gitignore. Git Good · Ch. 9 ↗
Chapter 5

Pick your tool

Part 2 · Environment
SnapGolden rule: use what the repo uses. The files in the root folder tell you which tool that is.
ToolThe repo has…Good forWatch out
venv + piprequirements.txtBuilt into Python, nothing extra to install. The safe default.Uses whatever Python version you already have.
uvpyproject.toml, uv.lock (or just requirements.txt)Very fast drop-in for venv + pip, and it can download the exact Python version the repo needs.Newer tool; one extra install (brew install uv).
condaenvironment.ymlNon-Python dependencies: CUDA toolkit, C libraries, some scientific packages.Slower and heavier. Mixing conda and pip installs can get messy.
Check the Python version first
SamThe README says “tested with Python 3.10.” I have 3.13. Does that matter?
SnapOften, yes! Old pinned packages may not exist for a newer Python. Match the version the authors used.
$ python3 --version
Python 3.13.1
# uv and conda can both install 3.10 just for this project
Hints in the repo 
requirements.txt
torch==1.13.1      ← exact pin: authors used this
numpy>=1.21,<1.24  ← a range
transformers       ← no pin: latest (risky!)
-e .               ← also install this repo

Unpinned packages are the #1 reason old research code breaks: today's “latest” is not what the authors had.

Chapter 6

Three recipes

Part 2 · Environment
venv + pip 
# inside the repo folder
$ python3 -m venv .venv
$ source .venv/bin/activate
(.venv) $ python -m pip install --upgrade pip
(.venv) $ pip install -r requirements.txt
# done for the day
(.venv) $ deactivate

Windows (PowerShell): .venv\Scripts\activate. See Appendix · Windows

uv 
# repo has requirements.txt
$ uv venv --python 3.10
$ source .venv/bin/activate
(.venv) $ uv pip install -r requirements.txt

# repo has pyproject.toml + uv.lock
$ uv sync
$ uv run python -m fancy_model.train

uv run uses the project's environment without you activating it.

conda 
# repo has environment.yml
$ conda env create -f environment.yml
$ conda activate fancy-model
(fancy-model) $ conda env list

# no environment.yml? make one by hand
$ conda create -n fancy python=3.10
$ conda activate fancy
(fancy) $ pip install -r requirements.txt

Install conda packages first, pip packages last. Don't activate a venv inside a conda env.

Chapter 7

Install & check

Part 2 · Environment
Am I in the right box?
SnapNo (.venv) at the start of your prompt? Then pip install puts packages in the wrong place.
(.venv) $ which python
/Users/ada/fancy-model/.venv/bin/python   ✓
(.venv) $ python -c "import torch; print(torch.__version__)"
1.13.1
(.venv) $ pip list | grep -i numpy

If which python points to /usr/bin/python or another project's folder, activate the right environment first.

Install the repo itself

If there's a pyproject.toml or setup.py, the repo is a package. Install it in editable mode:

(.venv) $ pip install -e .

-e means your edits to the source take effect immediately, with no reinstall. After this, import fancy_model works from any folder.

Freeze what worked 
(.venv) $ pip freeze > requirements-lock.txt
$ git add requirements-lock.txt
$ git commit -m "Record working package versions"

Future you (and your examiner) can rebuild exactly this environment. Git Good · Ch. 4 ↗

Miss your notebooks? Use the repo from Jupyter
SnapOnce the repo is installed, you can explore it in a notebook. Just make sure the notebook uses this environment as its kernel.
(.venv) $ pip install jupyterlab ipykernel
(.venv) $ python -m ipykernel install --user \
    --name fancy-model
(.venv) $ jupyter lab

In Jupyter, pick the fancy-model kernel. Wrong kernel = ModuleNotFoundError, even though you installed everything.

In [1]: from fancy_model.data import load_split
        from fancy_model.model import FancyModel
        ds = load_split("data/raw", "train")
        len(ds), ds[0].keys()
Out[1]: (12000, dict_keys(['text', 'label']))

Great for poking at the data and the model. Keep the real experiments as terminal commands, so they run the same way every time.

If the install itself fails
You see
Try
No matching distribution found for torch==1.8.0
That version doesn't exist for your Python version or computer. Use the Python version from the README, or relax the pin a little.
Failed building wheel for … / compiler errors
A package needs C/C++ build tools. Look for a newer version with prebuilt files, install it via conda, or on macOS run xcode-select --install.
ResolutionImpossible / conflicting dependencies
Two pins can't both be satisfied. Install the most important package (often torch) first, then the rest, and relax the pins the authors didn't really need.
Chapter 8

Start small

Part 3 · Run it
SnapDon't launch the 3-day training run first. Climb the stairs: each step fails fast and cheaply.

The last step, running the full experiment on a shared GPU cluster, is covered in Issue #3 · Share the GPU.

Steps 1 & 2 
(.venv) $ python -m fancy_model.train --help
(.venv) $ pytest -q tests/        # if there are tests

--help lists every option the script accepts. If even this crashes, it's an install problem, not a data or model problem.

Step 3 · tiny run 
(.venv) $ python -m fancy_model.train \
    --config configs/base.yaml \
    --epochs 1 --max_examples 200 \
    --device cpu --seed 42

Flag names differ per repo; take them from --help or the config file. Run commands from the repo root, because relative paths like data/raw depend on where you are.

SamMy number is 81.6 and the paper says 81.9. Did I fail?
SnapSmall differences are normal: random seeds, hardware, library versions. Report them honestly, and check if the paper averages several seeds.
Chapter 9

Read the traceback bottom-up

Part 3 · Run it
SamIt just printed a giant wall of text. I'm closing the terminal.
SnapWait! That wall is a confession. Python tells you what went wrong and where. It's the same red box you see under a broken Jupyter cell. Read it like a mystery: start from the ending.
Anatomy of a traceback 
3Traceback (most recent call last):
  File "/Users/ada/fancy-model/src/fancy_model/train.py", line 88, in <module>
    main(args)
  File "/Users/ada/fancy-model/src/fancy_model/train.py", line 41, in main
    train_ds = load_split(cfg.data_dir, "train")
2  File "/Users/ada/fancy-model/src/fancy_model/data.py", line 17, in load_split
    with open(os.path.join(path, f"{split}.jsonl")) as f:
1FileNotFoundError: [Errno 2] No such file or directory: 'data/raw/train.jsonl'
  1. 1Last line first. The error type (FileNotFoundError) and the message. Often this alone solves it.
  2. 2Go up to the last line in the repo's own code, not in a library under site-packages/. Open that file at that line number.
  3. 3The top shows how you got there, from your command down to the crash.

Verdict here: the data was never downloaded (run scripts/download_data.sh), or the script was started from the wrong folder (check with pwd).

Chapter 10

The error bestiary

Part 3 · Run it
SnapGood news: research code fails in the same few ways, over and over. Learn to recognise them.
Field guide
You seeIt usually meansTry
ModuleNotFoundError: No module named 'torch'Environment not activated, or the package isn't installed in it.which python → activate the env → pip install -r requirements.txt
ModuleNotFoundError: No module named 'fancy_model'The repo's own package isn't installed, or you're in the wrong folder.pip install -e ., or run from the repo root with python -m fancy_model.train
ImportError: cannot import name 'X' from 'Y'Your version of library Y is newer (or older) than the authors' version.pip show Y, then install the pinned version: pip install "Y==1.2.3"
AttributeError: module 'numpy' has no attribute 'float'Old code meets new NumPy (np.float was removed in 1.24).pip install "numpy<1.24", or replace np.float with float
FileNotFoundErrorData not downloaded, or relative paths and the wrong working directory.pwd; read the README data section; run from the repo root
CUDA out of memoryThe batch doesn't fit on your GPU.Smaller --batch_size, shorter inputs, or a bigger GPU on the cluster
Torch not compiled with CUDA enabled / no GPU foundThe code assumes an NVIDIA GPU, and your laptop doesn't have one.--device cpu (or mps on Apple Silicon) for the tiny run; use the cluster for the real run
Killed (and nothing else)The operating system ran out of RAM and stopped the process.Fewer examples, smaller batches, or a machine with more memory
KeyError: 'lr'The config file and the code disagree about names.grep -rn "lr" configs/ src/ to see which name each one uses

The debugging kit

Part 3 · Run it
Look inside: breakpoint() 
# add one line in data.py, just before the crash
def load_split(path, split):
    breakpoint()          # code pauses here
    ...

(Pdb) p path
'data/raw'
(Pdb) p os.getcwd()
'/Users/ada/fancy-model/scripts'  ← aha!
(Pdb) q

pdb commands: p x print, n next line, s step into, c continue, q quit. Remove the breakpoint() line when you're done.

Jump in after a crash 
(.venv) $ python -m pdb -c continue \
    -m fancy_model.train --epochs 1

Runs normally, and when it crashes, you land in pdb exactly at the failing line with all variables available. No need to edit the code.

Print the shapes 
print(type(batch), batch["input_ids"].shape)
<class 'dict'> torch.Size([32, 128])
Git is your lab notebook
SnapChange one thing at a time. When something works, commit it, so you know exactly which change fixed it.
$ git diff                     # what did I touch?
$ git commit -am "Pin numpy<1.24 to fix np.float error"
$ git restore src/model.py     # undo a failed attempt

Git Good · Ch. 5: diff & restore ↗

Search like a pro
  1. Copy the last line of the error, minus your own paths, into a search engine.
  2. Check the repo's GitHub Issues, including closed ones. Someone probably hit it before you.
  3. Read the paper's appendix: hyperparameters and hardware often live there.

Chapter 13

From notebook to script

Part 4 · Your own code
Next step: your own experiments
SamMy notebook works fine. Why would I turn it into a script?
SnapBecause a batch job on a cluster has no browser and nobody clicking “Run”. It runs python train.py, top to bottom, once. And a script is easier to test, review in Git and reuse.
The hidden-state trap

Cells run in any order, and a deleted cell's variables live on until you restart. A notebook can “work” only because of something you ran an hour ago.

The honest test

In Jupyter: Kernel → Restart Kernel and Run All Cells.

  1. It crashes? A cell depends on something that no longer exists.
  2. Different numbers? The order of running mattered.
  3. Same result, top to bottom? Ready to export.
Step 1 · Export 
$ jupyter nbconvert --to script analysis.ipynb
[NbConvertApp] Writing … to analysis.py
Lines that start with ! or % (!pip install …, %matplotlib inline) become get_ipython() calls that fail in plain Python. Delete them, and install packages in your environment instead (Chapter 6).
Step 2 · From cells to functions

Before: the raw export

# In[3]:

After: train.py

import argparse
from pathlib import Path
import pandas as pd
from sklearn.linear_model import LogisticRegression
from sklearn.model_selection import train_test_split

def load_data(path):
    return pd.read_csv(path).dropna()

def train(X, y, C):
    return LogisticRegression(C=C).fit(X, y)

def main():
    p = argparse.ArgumentParser()
    p.add_argument("--data", type=Path, default=Path("data/raw.csv"))
    p.add_argument("--C", type=float, default=0.5)
    p.add_argument("--seed", type=int, default=42)
    args = p.parse_args()

    df = load_data(args.data)
    X, y = df.drop(columns="label"), df["label"]
    X_tr, X_te, y_tr, y_te = train_test_split(
        X, y, random_state=args.seed)
    model = train(X_tr, y_tr, args.C)
    print(f"accuracy: {model.score(X_te, y_te):.3f}")

if __name__ == "__main__":                      5
    main()
  1. 1Hard-coded path → a --data argument with a relative default. Appendix · Paths
  2. 2No random seed → --seed, so every run splits the data the same way.
  3. 3Where's In[4]? A deleted cell. If anything still depended on it, the honest test would have told you.
  4. 4A bare last line only displays in a notebook. A script must print() or save it.
  5. 5if __name__ == "__main__": runs main() when you call the script, but not when a notebook imports its functions (Step 3).
$ python train.py --C 0.1 --seed 1
accuracy: 0.843
Step 3 · Keep the notebook, import the code 
In [1]: %load_ext autoreload
        %autoreload 2
        from train import load_data, train
        df = load_data("data/raw.csv")
        df.head()

The notebook stays your place to explore and plot; the logic lives in train.py. %autoreload 2 picks up your edits to train.py without restarting the kernel. Run the notebook from the project folder so import train finds the file.

Plots in scripts 
plt.plot(losses)
plt.savefig("results/loss.png", dpi=150)
plt.close()

Batch jobs have no screen: plt.show() displays nothing. Save figures to files instead.

Ready for the cluster?
  1. Restart & Run All gives the same result.
  2. python train.py runs from the project folder.
  3. No ! or % lines left in the script.
  4. No hard-coded paths; settings are arguments or a config file.
  5. A fixed random seed.
  6. Results and figures are saved to files.
  7. Dependencies recorded in requirements.txt (Chapter 7).
  8. Committed and pushed. Issue #1 · Ch. 10

All yes? Then the script is ready to run as a batch job. Issue #3 · Slurm
